## F1 账户接入

| 要求 | 状态 | 实现位置 | 验证方式 |
|---|---|---|---|
| 手机号 + 验证码 + 两步验证登录 | 🟡 | `tg/login.py: send_code / verify_code`；API `POST /api/accounts/{id}/login/send_code`、`/login/verify` | 后台添加账号 → 点登录 → 收码 → 输码；开两步验证的会二次要密码 |

| 多账号并行，独立会话/人设/开关/代理 | ✅ | `tg/manager.py: AccountManager`（每账号一个 runner + 独立任务）；`Account.persona_id / proxy / ai_enabled` | 添加两个号，分别启停互不影响 |
| 设备指纹可配置且稳定 | ✅ | `Account.device_model / system_version / app_version / lang_code`，登录与重连都用同一组 | 账号编辑里改型号，重登后 Telegram 设备列表显示一致 |
| SOCKS5 / MTProxy，一账号一出口 | ✅ | `AccountManager._build_proxy`（socks4/5、http、mtproxy）；`Account.proxy` | 账号里配代理后 `last_error` 为空且能上线 |

## 拟人化硬指标

| 指标 | 状态 | 实现 | 实测 |
|---|---|---|---|
| 打字时长按字数（3-5 字/秒） | ✅ | `typing.typing_seconds`；`human_send` 里用 `client.action(peer,'typing')` 期间 sleep | 自测：「嗯」1.2s vs 长句 7.8s |
| 一条回复拆 1-3 条 | ✅ | `typing.split_messages`（空行 > 句末标点 > 逗号） | 自测：长句拆 3 条 |
| 条间 1-3 秒 | ✅ | `SendPlan.gaps` | 自测：1.37s / 2.74s |
| 已读随机 3-90 秒 | ✅ | `read_delay`（三角分布，峰值 12s）+ 先 `send_read_acknowledge` 再打字 | 自测：14.4s / 24.4s |
| 陌生首条 10-60 秒 | ✅ | `read_delay(is_stranger=True)` | 自测：13.2s |
| 按人设作息模拟在线 | ✅ | `in_active_hours` + `next_active_time`（非活跃时段延后回复）+ `online_jitter` 8% 不在手机旁 | 自测：凌晨判定为不在线 |
| 同批次开场白全部不同 | ✅ | 负例注入 + `used` 去重 | 任务目标列表可对比 |

## 风控与预热

| 要求 | 状态 | 实现 |
|---|---|---|
| 新号 24-48h 静默，仅被动回复 | ✅ | `RateLimiter.proactive_daily_cap()`：<36h 返回 0；`handlers` 对被动回复放行 |
| 首周主动私聊个位数，逐周放量 | ✅ | 36h 后第 N 周 = `8 * 2^N`，上限为账号日上限 |
| 分钟/小时/天三级上限，可配默认保守 | ✅ | `RL_MINUTE=6 / RL_HOUR=40 / RL_DAY=150`；`Account.rate_limits` 覆盖；主动发起再除 2/3 |
| 一号一 IP、设备指纹稳定 | ✅ | `Account.proxy` + `device_*` 固定；登录与重连同一组参数 |
| FloodWait 精确等待不轰炸 | ✅ | 捕获后写冷却 key，期间 `check()` 直接拒绝 |

## 禁止事项自查

| 禁止 | 状态 | 说明 |
|---|---|---|
| 用 Bot API 冒充接管账号 | ✅ 未违反 | 账号侧全部走 Telethon MTProto（`StringSession` + 用户登录）；Bot API 只用于独立的控制 bot |
